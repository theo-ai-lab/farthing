via docker compose, Stripe test mode, both workers split by credential, the
approval inbox behind the dev proxy). Everything below is observed output, not
test-suite assertion.

## Defects found only by running live (all fixed same day)

1. **Workflow-sandbox module identity** — the package `__init__` imports
   `.domain`/`.policy`, so the sandbox planted its own copies before the workflow
   module's pass-through imports ran; `decide`'s enum identity checks then failed
   and every eligible ticket escalated as `unknown_action_type`. The failure
   direction was the safe one ($0 moved), but the fix is runner-level
   pass-through of the pure core (`worker.workflow_sandbox_runner`), locked by
   `tests/test_workflow_sandbox.py`.
2. **Approval-gate visibility lifecycle** — workflows kept
   `farthing_state='awaiting_approval'` after completing, so the inbox scanned
   completed workflows forever; and a query to a completed workflow with no live
   worker parks indefinitely, hanging the inbox page. Fixed by advancing the
   state on every gate exit (denied / approved / refunded / dead_lettered), by
   filtering the inbox scan to `ExecutionStatus = 'Running'`, and by bounding
   every inbox query with an RPC timeout.
3. **`python-multipart` missing** — the approve route takes form data; FastAPI
   needs the package at import time. Never seen offline because no test imports
   the app.
4. **Red-team harness robustness** — a hung inbox crashed the probe with a
   traceback instead of recording a FAIL; timeouts now land as
   `FAIL <-- NO RESPONSE`.

The offline suite (83 tests, 152-case golden set) could not have caught 1–3:
they only exist where real serialization, real process boundaries, and real
package imports meet.
